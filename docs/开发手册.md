# S-DES 密码实验台开发手册

## 1. 项目定位

本项目是信息安全导论作业 1 的 Python + PySide6 实现，采用“无 GUI 核心 + 桌面界面适配”的结构。算法模块可以独立导入和测试，界面模块负责输入校验、状态展示、进度更新和用户操作编排。

## 2. 目录与职责

```text
.
├─ main.py                         # 启动 QApplication 并显示主窗口
├─ pyproject.toml                  # 项目元数据和 pytest 配置
├─ requirements.txt                # 运行与测试依赖
├─ sdes_app/
│  ├─ constants.py                 # 算法参数，只保存常量
│  ├─ core.py                      # 8 bit S-DES 核心运算
│  ├─ text_cipher.py               # ASCII 字节模式适配
│  ├─ bruteforce.py                # 1024 个密钥遍历
│  ├─ collision_analysis.py        # 碰撞和等价类分析
│  ├─ gui.py                       # PySide6 窗口、页面和信号
│  ├─ styles.py                    # 全局 Qt 样式表
│  └─ __init__.py                  # 公共 API 汇总
├─ tests/                          # 单元测试和 GUI 冒烟测试
├─ scripts/capture_ui.py           # 离屏生成界面截图
└─ docs/                           # 用户、开发、接口及关卡说明
```

依赖方向应保持为：

```text
constants → core → text_cipher / bruteforce / collision_analysis → gui
                                      styles ───────────────────────→ gui
```

核心模块不得反向导入 `gui.py`，这样可以在无窗口环境中运行算法测试。

## 3. 开发环境

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -B -m pytest -q -p no:cacheprovider
python main.py
```

`pyproject.toml` 要求 Python 3.10 或更高版本；测试搜索路径为 `tests`，项目根目录已加入 `pythonpath`。

## 4. 算法实现约定

### 4.1 参数集中管理

`constants.py` 只保存作业要求的置换表和 S-Box。修改参数时应在该文件集中完成，不要在界面或测试中复制一份新的表。

### 4.2 连续移位密钥生成

`generate_subkeys()` 使用连续移位规则：

```text
P10(K) → C0、D0
LeftShift¹(C0、D0) → C1、D1 → P8 → k1
LeftShift²(C1、D1) → C2、D2 → P8 → k2
```

解密不重新生成另一套密钥，只在两轮运算中以 `k2`、`k1` 的顺序使用相同的子密钥。

### 4.3 核心数据约束

- 分组为固定 8 bit；
- 主密钥为固定 10 bit；
- 所有二进制输入只允许字符 `0` 和 `1`；
- 纯函数优先返回新值，不修改调用方传入的字符串或序列；
- 失败时使用 `TypeError` 表示类型错误，使用 `ValueError` 表示格式或取值错误。

## 5. 界面开发约定

`SDesWindow` 集中管理四个页面，但算法逻辑应委托给 `core.py`、`text_cipher.py`、`bruteforce.py` 和 `collision_analysis.py`。新增控件时应遵循以下顺序：

1. 创建控件并设置对象名、尺寸策略和提示文字；
2. 将信号连接到页面级槽函数；
3. 槽函数只负责读取输入、调用领域模块、更新视图和错误提示；
4. 长时间任务使用现有的定时器/进度回调机制，避免阻塞主线程；
5. 样式优先修改 `styles.py`，避免在单个控件上重复写大型样式表。

中文界面文字使用宋体回退字体，英文字母和数字使用 Times New Roman；新增页面应复用现有颜色、边框、提示框和滚动条样式。

## 6. 命名与注释规范

- 函数、变量使用有意义的 snake_case；类使用 PascalCase；常量使用全大写下划线命名；
- 避免使用没有上下文含义的单字母变量，循环索引等临时变量除外；
- 公共函数和数据类提供简洁 docstring，说明用途、输入、输出和关键限制；
- 注释只解释算法规则、特殊参数或不明显的实现原因；
- 不写与代码逐字重复的注释，不保留过时注释；
- 每次修改算法规则时同步更新测试、接口文档、用户指南和截图说明。

## 7. 测试策略

### 7.1 单元测试

- `test_core.py`：置换、连续移位、加解密、轨迹和输入校验；
- `test_text_cipher.py`：ASCII 编解码、十六进制/二进制解析和非法输入；
- `test_bruteforce.py`：多组明密文匹配、数量校验和密钥遍历；
- `test_collision_analysis.py`：候选密钥、碰撞统计和等价类；
- `test_gui.py`：四个页面的关键操作流程和界面数据传递。

### 7.2 回归检查

执行：

```powershell
python -B -m pytest -q -p no:cacheprovider
```

如果修改了算法参数，还应重新检查第一关示例、第三关文本往返、第四关候选密钥和第五关统计结果。第二关需要重新与其他小组交换向量进行交叉测试。

### 7.3 截图检查

```powershell
python scripts\capture_ui.py
```

该脚本在离屏 Qt 环境中依次生成四个页面截图，输出到 `docs/screenshots`。修改界面布局后应打开截图检查文字重叠、滚动区域、按钮状态和字体回退是否正常。

## 8. 扩展功能的实现流程

新增一个分析能力时，建议按以下顺序处理：

1. 在独立模块中定义数据类和纯函数；
2. 为正常输入、边界输入和错误输入补充测试；
3. 在 `__init__.py` 中决定是否将接口公开；
4. 在 `gui.py` 中只添加输入绑定、调用和结果呈现；
5. 更新接口文档和用户指南；
6. 重新运行测试和截图脚本。

## 9. 发布检查

- 使用全新虚拟环境安装依赖后可以启动；
- `pytest` 全部通过；
- 文档中的命令、示例输入和算法结果与代码一致；
- 不包含 `.venv`、缓存、临时文件或个人 IDE 配置；
- 变更记录能够说明算法参数、界面或文档的修改范围。
